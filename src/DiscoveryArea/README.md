# Discovery

Group fields use stable IDs with current display names. Refresh group-dependent
controls after renames, and migrate conditional rule labels with their assigned
colors and conflict resolutions so existing appearance settings stay intact.

`controllers/main_controller.py` composes the exploration UI. `service.py` owns
projection workflows; `metadata_access.py` supplies cached column-oriented data.
`repository.py`, `snapshot_repository.py`, `presets_repository.py`, and
`arrangement_repository.py` own their distinct persisted concepts.

- [canvas](canvas/README.md): scene contracts, interaction and native rendering.
- [discovery_methods](discovery_methods/README.md): projection algorithms.
- [thumbnails](thumbnails/README.md): variant storage, resolution and decoding.
- [controllers](controllers/README.md): panels and asynchronous coordination.

Keep metadata IDs canonical and arrays aligned. A snapshot restores its complete
saved state, including disabled controls; absent state must reset previous values.
Camera bounds and snapshot crop framing are separate concepts.

Grid and No Overlap transforms are available for every projection method,
including PCA, MDS, and imported coordinates. Arrangements preserve the original
projection coordinates and can be reset to the original view.

Snapshots capture their settings inline and never create or update component
presets. Inline state, including an explicitly empty or disabled component, is
authoritative. Preset references are read only to recover missing legacy state.
Snapshots also retain the active slicer values alongside its navigation recipe.
Presets belong to the current project. Panel menus expose **Apply preset…** and
**Save as preset…**. **Manage Presets...** at the bottom of each **Apply preset…**
submenu opens Settings directly on the Presets tab. No application-wide template
catalog is loaded. Applying a preset
copies settings; later edits do not overwrite that preset. Existing presets remain
available, including ones generated by earlier versions.


Metadata fields are listed once per table. Resolve their values from each plotted
item through parent links (for example, vector item → face → photo), preserving
the vector's item identity and row count. Agreeing paths coalesce; conflicting
parents leave an empty value. Old relationship field IDs remain aliases to stable
table fields in saved tooltip, pin, appearance, filter, and slicer settings.

Canvas toolbar controls have accessible names and explicit Tab order. In the
Layers bar, the checkbox toggles visibility and the adjacent arrow toggles
settings, even for a hidden layer. Enter on the checkbox and its right-click
menu also open settings. Clicking outside the popover closes it.
Escape in the settings window closes it and returns focus to the arrow.

Mapped appearance always exposes saved group fields, including clustering results
with more categories than the ordinary metadata limit. Point and border mappings
include every present group value and generate extra palette colors as needed.

The automatic Random view stays selectable alongside saved projections and
running jobs. The canvas always loads the highlighted projection, and refreshing
the list preserves the current selection. Random contains one point per current
Items row, independent of media links, source records, and saved coordinates.
Adding or removing Items updates its points while retaining the positions of
existing items. Loading it writes no projection or preset; legacy automatic
coordinates are ignored and do not block metadata replacement. Saved
snapshots, pins, marked areas, and explicit projections remain real dependencies.
Discovery resolves asset-only analysis IDs through the project registry and can
load saved coordinates without metadata rows. Missing metadata has empty values.

Snapshots expose **Citations…** from their context and panel menus.
New snapshot captures freeze a methods report alongside their inline filter,
slicer, and transform settings. Reports include projection/model provenance and
clustering records referenced by group-set fields. Legacy snapshots show the
available settings and explicit provenance gaps. `snapshot_provenance.py` owns
assembly; `settings_provenance.py` reports applied transforms and filter settings
without evaluating data or loading coordinates.

Hover tooltips show up to 300 characters per metadata value, with an ellipsis
for longer values. Text wraps within a maximum 360 px section, including URLs
and identifiers without spaces. Short tooltips remain compact; preview size
and placement are independent. Full metadata stays unchanged.

Tooltip Preview Assets also support generated audio/video clips and animated
GIFs. Posters load on hover; playback starts after 200 ms on the same Item.
Audio/video use the saved Loop toggle and play any audio included in the clip;
videos retain their final frame when Loop is off until the tooltip closes or
changes. Audio waveforms show a red playhead updated at 25 Hz while playing;
it resets on looping and stays at the end after Once playback, without changing
the poster or canvas. GIFs retain their encoded timing and repeats. Size-slider
previews show only the poster. Missing previews show a local status without
opening source media.
`controllers/tooltip_preview_controller.py` owns the single visible playback
session. `tooltip_preview_service.py` resolves one generated clip in a lazy
worker, coalesces pending requests, and streams GIFs through a two-message
queue. Hiding the tooltip, leaving Discovery, switching projects, or changing
Preview Assets cancels loading and stops playback. The canvas renderer and
its static thumbnail atlas do not participate in playback.

Saved **Text excerpts** also appear in Tooltip Settings' Preview Assets selector.
Selecting text shows the Designer-owned font and font-size row (8–36 pt, default
12). The existing preview-size row and icon remain visible; its slider controls
text box width (25–500 px) independently of font size, matching Pins. Every tooltip
settings change previews the current Item (or first
available Item), even when canvas hover tooltips are disabled. Feedback stays
visible while editing and closes with settings. Feedback is placed outside the
settings window and repositioned when either box moves or resizes. The font menu uses Figures'
curated families available to Qt, preserving saved families outside that list
without initializing plotting. The application font is the default; font selection,
font size, and preview width are saved with the project's tooltip settings.
Text and background follow light/dark theme colors, with no per-asset styling.

The existing latest-only tooltip worker reads one saved excerpt by set and Item
without opening the source or initializing storage. Missing excerpts show a local
message. Literal markup, paragraph breaks, and Unicode are preserved; reading
direction sets automatic alignment. Text wraps within the selected width and a bounded number
of lines, with ellipses for source omissions or display clipping. Font changes
reflow the loaded excerpt without rereading it. Text is not offered for canvas
image previews.

Pins also accept saved text excerpts. Their Preview Assets section shows the same
curated Font and Font size controls (8–36 pt), independent of metadata typography
and tooltip settings. The existing asset-size slider sets the text preview width;
Loop is hidden for text. Text and background follow the application theme.
`pin_text_preview_controller.py` prepares only visible pin excerpts through a
single background worker, cancels replaced requests, and rejects stale results.
`pin_text_preview_service.py` reads saved text without opening the source and
returns plain strings, never images. `canvas/pin_text.py` caches bounded wrapping
and shares layout metrics with the native pin overlay and export painter. Both
draw text directly at the selected font size. Width changes reflow the excerpt;
font, width, and theme changes reuse loaded text without reading storage again.
Appearance is saved with pin display settings; loaded excerpts are transient.

Pins accept the same generated Preview Assets with explicit Play/Pause and a
clickable progress track. Audio shows a red playhead; audio/video use the Pins
Loop setting (off by default), while GIFs retain their encoded repeat settings.
Playback continues when the pointer leaves. Starting another pin releases the
previous decoder and remembers its position. Hidden, removed, fully covered, or
offscreen pins stop playback, as do project changes and leaving Discovery.
Tooltip autoplay is suppressed while a pin plays. No source media is opened.
`controllers/pin_playback_controller.py` owns the player and bounded background
work; `canvas/pin_media.py` supplies small transient surfaces using existing pin
geometry and input routing. Frame updates do not serialize pins or rebuild the
canvas scene. Snapshots and exports retain the generated posters, without
playback controls or playheads.

Individual-item dialogs show the selected permanent item's metadata through the
Items service: the same column labels, order, and resolved linked values, without
Discovery-only mapping fields. The row is fetched by primary key. The field-name
column starts at a bounded width and is resizable; tooltips retain full contents.

Individual-item dialogs offer named media sources with separate image, video,
audio, and read-only text views. The selector includes only file extensions
in the common-format contract in `media_preview_service.py`, shared with the
packaged playback audit. Video includes MPEG as well as MP4/MOV/MKV/WebM/AVI;
transport streams and WMA are excluded. TXT, Markdown, CSV/TSV, JSON and JSONL
display as plain text; PDF and
Word documents are not supported. JSONL record sources show only the linked
record. Text reads run off the GUI thread and preview up to 200,000 characters,
with an explicit notice when truncated. Switching sources cancels pending text
reads and stops playback without changing the canvas preview source.
