# Security policy

EIDORA is prototype software. Security fixes target the current development
branch and the latest published release; older prototype versions are not
maintained as separate security branches.

Use GitHub's **Security → Report a vulnerability** on the EIDORA repository for
private reports. Include the affected version/commit, impact, and a minimal
synthetic reproduction. Do not post credentials, private collections, or exploit
details in public issues or pull requests. If private reporting is not available,
use the contact channel on [eidora.org](https://eidora.org) to request a private
reporting route before sending sensitive details.

The maintainer assesses reports and coordinates a fix and disclosure. No fixed
response-time guarantee is made.

Official releases are approved by the maintainer. Forks and unsigned CI artifacts
are development builds. Signing credentials and release publication access are
kept outside the public source repository. See [release policy](packaging/RELEASING.md).
